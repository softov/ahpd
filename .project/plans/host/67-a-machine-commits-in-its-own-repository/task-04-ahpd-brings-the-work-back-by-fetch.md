## Objective

`ComputerPort.bringBack(id)` fetches the commits a machine's branch has beyond the host's into the host's repository and moves the host's branch to them where that is a fast-forward with nothing staged, reading nothing from the machine but a bundle on a pipe.

## Files

- `UPDATE: packages/sdk/src/types/computers.ts` - `bringBack?(id: string): Promise<BroughtBack | undefined>`; `BroughtBack` is `{ moved: boolean; waiting?: string }`, the hidden ref when the work waits.
- `UPDATE: packages/computer/src/runtime.ts` - a byte stream out of `docker exec` (and the dev container road) into a file made `0600` in a fresh private directory; `bringBack` runs `git bundle create - refs/heads/<branch> --not <last>` in the machine, then on the host `git -c transfer.fsckObjects=true fetch --no-tags --no-write-fetch-head <file> +refs/heads/<branch>:refs/ahpd/machines/<machine>/<branch>`, then, where the old tip is an ancestor and `diff --cached --quiet` holds, `update-ref refs/heads/<branch> <new> <old>`, `reset -q` in the tree and `update-ref -d` of the hidden ref.
- `UPDATE: packages/computer/src/plugin.ts` - the port's `bringBack` for machines it made.
- `UPDATE: packages/computer/test/computer-git-fetch.test.ts` and `computer-disposable.test.ts` - the cases below.

## Steps

1. Failing case first, real Docker: a commit in the machine is not on the host's branch after `bringBack`; today there is no `bringBack`.
2. The byte stream: `ran` stays for text; the new one writes stdout straight to the file.
3. The host's fetch reads only the file; it never names a path inside the machine's volume.
4. Diverged, or something staged: keep the hidden ref, log `the work of <machine> waits in refs/ahpd/machines/<machine>/<branch>: <branch> moved on the host` (or `the index holds staged changes`), answer `waiting`.
5. Empty bundle: answer `{ moved: false }`, no fetch.

## Validation

- `computer-git-fetch.test.ts`: a machine commit is on the host branch after `bringBack`, with a clean host `git status`; a bundle whose pack fails fsck is refused and the host branch is untouched; a host commit made meanwhile leaves the work under the hidden ref; staged host changes the same; nothing new is `{ moved: false }`; the private file is gone after each case.
- `computer-disposable.test.ts`, scripted Docker: the argv of the bundle and the fetch, and that the fetch names only the file.
- `npx tsc -b` clean; `npx vitest run packages/computer` passes.

## Resume

- **Implemented** 2026-10-06 on `build/agents/c016a0e4`.
- `packages/sdk/src/types/computers.ts`: `BroughtBack` (`{ moved: boolean; waiting?: string }`) and `ComputerPort.bringBack?(id)` are new, with the doc comment saying what a port that cannot bring anything back answers (it leaves the call out) and where the work waits. `BroughtBack` is exported from `packages/sdk/src/types/index.ts`.
- `gitdir.ts`: `GIT_VOLUME` (`ahpd-git`) is the prefix `gitVolumeOf` builds from, new because the volume's own name is read back from a machine's mounts. `treeOf(mounts)` is new and answers the tree a machine was given: the directory above the mount that is the gitfile this host wrote, or above a mount of `ahpd-git-<machine>` at a target whose basename is `.git`. It reads the mounts because nothing else names the folder of a `docker run` machine - not a label, and not a path the caller holds - and it takes the mount's own spelling so a folder reached through a link is the machine's spelling of it, as `git -C <tree>` in the machine needs.
- `runtime.ts`: `ComputerRuntime.bringBack`; `argvInto` (the two roads `exec` takes - a dev container's `execArgv` and every other machine's labelled user - in one place, with `exec` rewritten in terms of it, so a command in a machine is reached one way in this file); `poured` (a child's stdout straight into a file, only stderr read as text, and the write waited for as well as the process); `hostGit` (spawnSync with `gitArgv`, in the tree and never inside the machine's volume, answering a code rather than throwing); `mountsOf`.
- The flow: the branch is asked of the machine's own git (`symbolic-ref -q --short HEAD`); `from` is the hidden ref where it exists, else the tree's `HEAD`; `git -C <tree> bundle create - <ref> --not <from>` is poured into `<tmpdir>/ahpd-bringback-XXXX/work.bundle` (the directory `mkdtemp`, the file `0600`); the host runs `git -c transfer.fsckObjects=true fetch --no-tags --no-write-fetch-head <file> +<ref>:refs/ahpd/machines/<id>/<branch>`; then `merge-base --is-ancestor <old> <new>` and `diff --cached --quiet`, then `update-ref refs/heads/<branch> <new> <old>`, `reset -q` and `update-ref -d <hidden>`. The scratch directory goes in a `finally`, whether the fetch worked or not.
- The hidden ref names the id the caller holds, `refs/ahpd/machines/<id>/<branch>` - not the name Docker answers for, which for a dev container is the CLI's own and is not what a session or the host tracks. A machine on no branch has no branch to name and bundles its `HEAD`, so its hidden ref is `refs/ahpd/machines/<id>/HEAD` and no branch of the host's is ever moved; the log line says `the machine is on no branch`.
- `from` is the hidden ref rather than the host's branch, which is the plan's own row: a bundle carries only what is new since the last fetch, so work that waited is not fetched twice, and the fetch that lands it is then measured against the branch's own tip for the fast-forward.
- Answers: `undefined` for a machine that is not here (an `inspect` with no record); `{ moved: false }` for a machine with no git directory of its own or one under `open` (its label is not `fetch`), for one whose mounts name no tree, for a tree with no commit at all, for git's own `Refusing to create empty bundle`, and for the case where the branch already holds the machine's commit (the hidden ref is then dropped, since it keeps nothing). `{ moved: false, waiting }` where the machine is on no branch, where the branch moved on the host, and where the index holds staged changes - with the task's two sentences, and git's own words thrown where the bundle or the fetch fails (an fsck refusal reaches the caller as git's `missingAuthor`/`fsck error in packed object`).

- **Review round** 2026-10-06: two defects in what the bring-back reads, and in how much of it there is.
  - **A branch the host does not have never landed.** `old` came from `rev-parse <ref>` without `--verify`, so a ref the host had none of answered the ref's own name rather than nothing, and the ancestor check then read a branch that was never there as one that had moved on. Every read of the host's refs is now `hostRef`, which is `rev-parse --verify --quiet` and answers `''` for a ref that is not there; an empty `old` means the host has no branch by that name, so it is made at the machine's commit with no ancestry check - there is no history of the host's for it to lead on from - and the staged-changes rule still applies where the branch is the one the host's tree has checked out. The `rev-parse` calls in the bring-back and follow paths were audited with it: the rest already carried `--verify --quiet`.
  - **Only the branch the machine was on came back.** `bringBackOfMachine` now asks the machine for `for-each-ref refs/heads/` as well as its `HEAD`'s branch, and each of them goes through the new `bringBackBranch` under a hidden ref of its own, `refs/ahpd/machines/<id>/<branch>`. A branch's baseline is the hidden ref where it exists, else the host's branch of that name - what the machine was seeded from - else the host's `HEAD`, so a branch the host has never had is measured from the seed; the ancestry check, the staged-changes check, the `update-ref` and the `reset -q` now apply per branch, the last two only where the branch is the one the host's tree has checked out, and the answer's `waiting` names every ref that is waiting rather than one.
  - A consequence for the tests as much as for the code: a machine's git is now asked where its branch is, not only which branch it is on and for a bundle, so the three scripted cases in `computer-disposable.test.ts` that script a machine's git gained the answer (`{ when: 'rev-parse', out: '<commit>' }`), and the fixture's comment above `answers` says three answers rather than two.
  - Two real-Docker cases were added, both failing first: `makes a branch on the host that the machine made and the host never had` (the machine runs `git checkout -b fix` and commits, the turn ends, `refs/heads/fix` is on the host at that commit and the hidden ref is gone) and `brings back every branch the machine holds, not only the one it is on` (a commit on `main`, `checkout -b spike` and a commit there, back to `main`, the turn ends, and both commits are on the host). `computer-git-fetch.test.ts` now holds 22 real-Docker cases and all of them pass (136 s, run with Docker available).
