## Objective

A profile's `sessionTree` is `shared`, the default, or `copy`.
Under `copy`, the machine works in its own checkout in its volume at the tree's root path, nothing of the host's folder is mounted, its commits reach the host by `bringBack`, and the host's tree follows them with `merge --ff-only` (decision 1).

## Files

- `UPDATE: packages/computer/src/manifest.ts` - `Profile.sessionTree?: 'shared' | 'copy'`, documented beside `sessionFolder`.
- `UPDATE: packages/computer/src/plugin.ts` - the schema row, the reading, and `['sessionTree', ['shared', 'copy']]` in the answers check.
- `UPDATE: packages/computer/src/runtime.ts` - under `copy`, both routes mount the volume at `<repository ?? folder>` instead of binding it, with `objects/` read-only as under `shared`; the seed ends with `reset --hard -q`; `bringBack` runs `merge --ff-only <new>` in the host's tree in place of `update-ref` and `reset -q`; `follow` runs `merge --ff-only` in the machine where its tree is clean; `remove` fetches `git stash create` to `refs/ahpd/machines/<machine>/uncommitted` when the machine's tree is not clean.
- `UPDATE: packages/computer/test/computer-plugin.test.ts`, `computer-disposable.test.ts`, `computer-git-fetch.test.ts` - the cases below.

## Resume

- **Implemented** 2026-10-06 on `build/agents/c016a0e4`.
- `packages/computer/src/manifest.ts` gains `sessionTree?: 'shared' | 'copy'` on `Profile`, documented beside `sessionFolder`: `shared`, the default, binds the host's tree into the machine at its own path, and `copy` gives the machine a checkout of its own in its volume, mounted at that same path, with nothing of the host's tree bound. `packages/computer/src/plugin.ts` carries the schema row, the reading (`said.sessionTree === 'shared' || said.sessionTree === 'copy' ? { sessionTree: said.sessionTree } : {}`), `['sessionTree', ['shared', 'copy']]` among the answers a profile's options are checked against, and the session route's `withGit` call, which passes `profile.sessionTree` as the fifth argument. Nothing else reads the option: the `devcontainer://` route's own `withGit(asked, answer)` call passes no tree, so it stays `shared` (below).
- `withGit` takes `tree: SessionTree = 'shared'` and refuses a `copy` profile whose folder has no repository a machine for that session may be given, in one sentence naming the profile, the folder and the two ways out: under `copy` the host's folder is not bound at all, so a machine with no git directory would have no commit to be seeded at, no history through the alternates, and an empty volume that loses everything the agent writes in it. It also collapses the guard, `guardFor(guard, tree)` answering `fetch` under `copy`, and the collapsed guard is what everything downstream reads: `runsAsHost(asked.gitDir, at, held)` is asked with it, so a `copy` machine's commands run as the host user's uid:gid exactly as under `fetch` - which is what keeps the volume the tree lives in the host user's own - and the `ahpd.git` label of the machine is written from it.
- `packages/computer/src/gitdir.ts` gains `export type SessionTree = 'shared' | 'copy'`, `guardFor`, and one arm: `guardedMounts(gitDir, root, state, guard, tree)` returns `gitMounts(gitDir, root, state, true)` at once where the tree is `copy`, which answers one bind - the host's `objects/` read-only at `MACHINE_OBJECTS` - and the volume `ahpd-git-<machine>` with `volume` set to the tree's own root path and `copy: true`. No gitfile bind, no read-only git bind: the volume holds the working tree and `.git` together, so there is nothing the host's git directory has to lend the machine but the history. `treeOf` and `copyOf` read a machine back out of its own mounts through `listedTree`.
- `listedTree` had to change with it, and that is a bug this task found rather than made: it recognized an ahpd volume by `Source` starting with `git-volume-`, and real Docker spells a named volume twice - `Source` is the driver's own path (`/var/lib/docker/volumes/ahpd-git-<machine>/_data`) and `Name` is the name the host gave it. Only the scripted Docker in `packages/computer/test/fixtures/docker.mjs` records the name in `Source`. So `listedTree` now reads `Name` where the record has one and falls back to `Source`, which is what makes `copy` work against real Docker at all. It also fixes a latent bug outside this task: a `shared` machine on a main checkout, whose tree can only be named by its volume's mount, was invisible to `treeOf` under real Docker too - every existing `bringBack` and `follow` case used a linked worktree, where the gitfile bind names the tree first, so nothing was exercised.
- `packages/computer/src/runtime.ts`: both routes read `const tree = spec.sessionTree ?? 'shared'` and hand it to `guardedMounts` beside the collapsed guard. The Docker route does not bind the folder or the repository root under `copy` (the volume's own mount lands at that path instead), and `seedGit` reads its root and its git directory out of `git.volume` under `copy` - the volume is the tree and `.git` is inside it - while its final `reset` is `--hard`, since the working tree in there is the volume's own and holds nothing yet: the checkout is the seed. Under `shared` nothing changed, and the host's own tree is still never written by the seed.
- The three moments after the seed are where `copy` differs. `bringBackOfMachine` takes a `copy` branch before the shared one's ancestor and staged-changes checks: nothing new is `update-ref -d` on the hidden ref and `{ moved: false }`; otherwise the host's tree runs `merge --ff-only <arrived>`, which is what the plan's row asks for, and where it refuses - the host changed a file the machine's commit writes, or the branch does not lead on - the work waits under the hidden ref and a line says so. The staged-changes check is deliberately not carried over: a merge does not unstage, so the merge's own refusal is the guard. `followOfMachine` dispatches to a new `followOfCopy`, which reads the host's branch and tip in the tree, and moves the machine only where three things hold - the machine's commit was fetched (a log line says the host has not fetched it), the host's tip leads on from it, and the machine's tree is clean, since `follow` under `copy` merges into the machine's own working tree and would otherwise eat what the agent has not committed. A detached host gives `update-ref --no-deref HEAD` and `reset --hard -q`; a branch gives `checkout -q -B <branch> <tip>` where it differs and `merge --ff-only`.
- `remove` keeps what the machine never committed, through a new `keepUncommitted(id, at, found, tree)` called after `bringBackOfMachine` and only under `copy`. It returns at once on an empty `status --porcelain`; else it runs `git stash create` in the machine, `update-ref refs/ahpd/uncommitted <commit>` there, and bundles that ref out of the machine on the same pipe task 04 uses, fetched by the host with `transfer.fsckObjects=true` into `refs/ahpd/machines/<machine>/uncommitted`, with `--not from` naming the host's tip where the ref is already known. The scratch file under `mkdtempSync(tmpdir(), 'ahpd-bringback-')` is removed in a `finally`, and the whole call is wrapped so a failure is a log line and the removal goes on - a machine that cannot be emptied is still a machine that has to go.
- The dev-container route's `copy` arm in `overrideOf` is written and unreachable today, and this is said plainly rather than tested: it makes the CLI's own `workspaceMount` the machine's volume, at `git.volume ?? root`, and drops the separate volume mount that would otherwise mount the same volume twice. It cannot be reached because `manifestOf` sets neither `gitDir` nor `gitGuard` nor `sessionTree`, and the only call site that passes a tree is the plugin route's, which never sets `spec.devcontainer`. This task's *Validation* names plugin, disposable and git-fetch and no dev-container case, so none was written; a later task that gives a dev container a session's git directory will find the arm waiting and needs a case for it.
- `packages/computer/test/computer-plugin.test.ts` gains three cases: `shared` spelled out and left out both bind the host's tree at its own path with no volume of the machine's own, while `copy` binds no such path and mounts the volume at the tree's root instead; a third answer (`both`) is refused at load naming the two; and a `copy` profile over a folder that is not a repository is refused in the sentence, while the same folder under `shared` is bound as it always was.
- `packages/computer/test/computer-disposable.test.ts` gains one case: the same repository, once through a `shared` profile and once through a `copy` one, with the `copy` machine's mounts exactly the objects bind and the volume at the tree's path, no bind of any path under the temporary directory but the objects, the host's refs byte for byte unchanged (the host's git does write `FETCH_HEAD` into its git directory, so the check is `for-each-ref` before and after rather than a directory listing), the label `ahpd.git=fetch`, and the seed of the `copy` machine holding `reset --hard -q` where the `shared` machine's holds no `reset --hard` at all.
- `packages/computer/test/computer-git-fetch.test.ts` gains four real-Docker cases under a heading of their own, each `it.skipIf(!DOCKER)` with `DOCKER_CASE = 120_000` as `computer-git-guard.test.ts` does: a file the copy machine writes and commits is in the host's folder and on the host's branch after `bringBack`, with `git status` there clean; a host change to the same file makes the merge refuse, the work waits under `refs/ahpd/machines/<machine>/main`, the branch does not move and the host's file is untouched; an uncommitted change at `remove` is in `refs/ahpd/machines/<machine>/uncommitted` on the host and readable through `git show`; and a host commit between turns reaches the machine on `follow` and moves it, while a further host commit plus uncommitted work in the machine leaves it where it was, with `M host.txt` in the machine's status and the `is not moved` line in the log.

And no remote, submodule or filter driver reaches a machine, so `git push` and LFS do not work in one; the plan's *Risks* already names both, the second for the built plan's `deferred.md`.
