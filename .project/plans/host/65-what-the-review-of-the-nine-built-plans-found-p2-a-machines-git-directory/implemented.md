A machine with a repository's git directory can commit in its worktree and can write nothing else there: the directory is read-only, with only the objects, refs, logs and the session's own worktree entry writable over it, and a main checkout's root is writable because `index`, `HEAD` and `COMMIT_EDITMSG` are files in it - with the eight paths git reads pinned back read-only. A git directory git answers that is not the folder's own is refused, in two layers, with one line naming the file that sent it there and no machine made. Paths are compared real and every bind lands at the spelling the machine mounts the tree at, so a session whose folder is a symbolic link is guarded like any other. A session folder below a repository's root brings that root only where its profile says `sessionRepository`, and a worktree's `index.lock` is removed only when the machine could have been holding it.

## What was built

- [`code://packages/computer/src/gitdir.ts`](../../../../packages/computer/src/gitdir.ts) - the writable allowlist and the two guards.
  - `gitMounts`: in a linked worktree, the git directory is read-only and what a commit writes is bound writable over it - `objects/` (with `objects/info/` read-only again, since `alternates` names where objects come from), `refs/`, `logs/`, and the session's own `worktrees/<name>/` entry, whose `config.worktree`, `commondir` and `gitdir` are pinned read-only. Everything else stays read-only: `hooks/`, `config`, `worktrees/`, `modules/`, and the worktree's own `.git` file. In a main checkout the git directory's root is writable, with `commondir` (written as `.`, naming the directory itself), `config.worktree`, `config`, `packed-refs`, `info/`, `hooks/`, `worktrees/` and `objects/info/` pinned over it, because git writes `index`, `HEAD` and `COMMIT_EDITMSG` as `<name>.lock` in the root and renames them into place - decision `a-machines-git-directory-is-read-only-but-what-a-commit-writes`. Whatever is missing is made on the host first, empty, so every bind has a source, and a source that is a symbolic link is refused.
  - `ownOf`: a git directory that is not the tree's own is refused before anything is made - a main checkout whose `.git` is not the directory git answered, or a worktree whose entry's `gitdir` does not name the tree's `.git` back. The comparisons are on real paths, so a tree reached through a link still matches.
  - `spellingOf`: every bind is written into the tree's spelling - the path the machine mounts the tree at - so a session whose folder is a link is guarded at the link rather than at a second, writable directory of its own inside the machine.
  - `gitInside` compares `realpath`s, so a link and its target are one tree, and `guardedMounts`/`runsAsHost` follow.
  - `releaseLock(entry, before, log)`: only an entry under some `worktrees/`, only its `index.lock`, and only where the lock's `mtime` is not after the machine stopped. A lock taken after that is host git's - `ahpd`'s own check, or a person committing in the worktree - and is left, with one line saying so.
- [`code://packages/computer/src/runtime.ts`](../../../../packages/computer/src/runtime.ts) - `stoppedAt(found)` reads `State.FinishedAt` from the record `remove` already inspects, and answers now where the container is still up (the zero time Docker writes) or the time cannot be read: a machine still running is stopped by the removal itself. It is read before `rm -f` and handed to `releaseLock`.
- [`code://packages/computer/src/plugin.ts`](../../../../packages/computer/src/plugin.ts) - `profilesOf` reads `sessionRepository: true` beside `sessionFolder`; `withGit(asked, root, guard, repository)` refuses the whole group - `repository`, the git directory beside it, and the acting-as-the-host-user flag - where the folder is below a repository's root and the profile does not say `sessionRepository`, logging `the profile does not say sessionRepository, so <folder> is mounted without <root>, the repository it is in, and without its git directory`. The folder itself still reaches the machine where the profile says `sessionFolder` - decision `a-session-folder-reaches-a-machine-only-where-its-profile-allows`.
- [`code://packages/computer/src/manifest.ts`](../../../../packages/computer/src/manifest.ts) - `Profile.sessionRepository`, documented as the operator's own opt-in to the host filesystem one step wider than the folder.
- [`code://packages/sdk/src/repo/worktrees.ts`](../../../../packages/sdk/src/repo/worktrees.ts) - `gitDir` asks once: `git rev-parse --path-format=absolute --git-common-dir --absolute-git-dir --show-toplevel`, answering `{ gitDir, worktreeDir, repository }`, so a caller sees the common directory, the tree's own, and the tree's root together. `GitDir` gained the required `worktreeDir`, and its doc says the answer is git's, not a check.
- [`code://packages/sdk/src/host/machines.ts`](../../../../packages/sdk/src/host/machines.ts) - `repositoryOf` checks before the machine is made: `stray` refuses a folder whose `.git` holds a `commondir` naming anything but the directory it is in - before git is even asked, since git would answer the repository it names - and `notOwn` refuses git's answer where it is not the folder's own, including where a rewritten entry's `gitdir` names another file. Both log one line naming the path and pass no `gitDir`, as a `rev-parse` failure does.
- [`code://docs/COMPUTER.md`](../../../../docs/COMPUTER.md) - the worktree paragraph now says what is read-only and what a commit writes, that only the folder's own git directory reaches a machine and what a `commondir` leading elsewhere means, and a `sessionRepository` row sits beside `sessionFolder`'s with the sentence on a folder below the root.

## Departures from the plan

- Task 01's step 1 asked that the first bind be the git directory with `readOnly: true` in both sessions. A main checkout is the exception the decision's own "Writable root, pinned files" says it is, and step 5 is what that case is: its root is `readOnly: false` with the read-only pins over it - six when this was written, eight after the review fix below - and the assertion for a worktree session's first bind is the read-only one.
- Task 02 named `gitdir.ts` and `machines.ts`; the check is in both, deliberately. The SDK's is the one that decides before a machine exists and names the file that misled git; the runtime's `ownOf` repeats it where the directories are about to be made, so a `MachineSpec` built by anything but the SDK cannot leave `hooks/`, `worktrees/` and `modules/` inside another repository. `computer-git-own.test.ts` keeps the second layer tested rather than dead.
- Task 02's `notOwn` is lenient where `<repository>/.git` is neither a file nor a directory: nothing is refused then, which is what keeps the existing fixtures that point at paths which do not exist working. Where the folder has no `.git` at all, git's answer stands as it did.
- `GitDir` gained a required `worktreeDir`, so the four fake answers in `packages/sdk/test/host-files.test.ts` and the two port cases in `packages/sdk/test/worktrees.test.ts` were updated with it.
- Task 03's step 1 named `gitInside`, `guardedMounts` and `runsAsHost`; the binds themselves also had to be spelled, which is `spellingOf` in `gitMounts`. Without it a link session's binds landed on the real path - a second, writable directory inside the machine - which is the same finding from the other side.
- Task 04's plan named the profile schema beside `sessionFolder`; the options' JSON schema lists neither `sessionFolder` nor a profile's other non-schema fields (`title`, `image`, `folder`, `disposable`), so `sessionRepository` is read in `profilesOf` and documented, and no schema row was invented.
- The plan's own checklist asked for a by-hand run of a disposable `isolation: worktree` session. It was not typed at a prompt: `computer-git-guard.test.ts` does exactly it - a real machine, real Docker, real git inside the container, committing onto the host's branch while the pins refuse a write - and the checklist row says so.
- Task 05's words did not ask for a line where a lock is kept; `releaseLock` writes one, naming the lock and that it was taken after the machine stopped. A leftover lock nothing explains is the reason. The scripted docker also gained `State.FinishedAt` (the zero time while a container is up, and what `stop` records), which the record had not carried.

## Review fixes

- A main checkout pinned six names and left two writable that the linked-worktree branch already pins. `<gitDir>/worktrees/<sibling>/commondir` is a file a machine can rewrite to point that sibling worktree at a directory it fills, whose `config` sets `core.fsmonitor` - and the host user's next git in that worktree runs it, which the review reproduced with git 2.47.3 - and `objects/info/alternates` names another object store the same way. Both are read-only binds now, made on the host first where missing, so the list is eight. The case is `pins what a sibling worktree and the object store read on a main checkout too` in `computer-git-own.test.ts`: the bind list for a main checkout with a sibling worktree holds both read-only and the root stays writable, and it failed first on `expected false to be true` for `worktrees/`. The Docker-backed case in `computer-git-guard.test.ts` now `touch`es `<gitDir>/worktrees/tree/commondir` and `<gitDir>/objects/info/alternates` among the paths that must refuse a write, and `computer-disposable.test.ts`'s exact mount list for a main checkout carries both. The decision's main-checkout list names them and says where they came from.
- What is *not* fixed here, and is deliberately left: the writable binds themselves. A machine may still plant a symbolic link under `<gitDir>/logs/` or `<gitDir>/objects/` while it runs - a name that does not exist yet - and the host's git appends through it when it next writes there. Closing that means a machine's git gets a git directory of its own that the host fetches from, which is a new plan (host/67) Softov decided on 2026-10-06, not a bind to add: pinning `logs/` or `objects/` read-only is what a commit needs writable. The writable binds remain exposed to a link planted under them until host/67 lands.
