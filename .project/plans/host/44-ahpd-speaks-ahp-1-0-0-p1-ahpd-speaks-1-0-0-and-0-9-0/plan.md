## Goal

ahpd is built on the 1.0.0 package and answers `initialize` with the highest version the client offers among 1.0.0 and 0.9.0, refusing anything else with `-32005` and the list it speaks.
A nested ahpd that answers 0.9.0 is still a host this one talks to, and the strict schema the wire test reads always comes from the package that is installed.

## Reconnaissance

The files read and the patterns to reuse are the `refs` above, each with its note.

### Searches performed

- `rg -c "protocolVersions: \['0.8.0'\]" packages examples` - 40 literal offers in 22 test files, and `host.test.ts` makes 92 more through `hello(['0.8.0'])`; 107 literal offers are `['0.9.0']`, which 1.0.0 still accepts.
- `rg -n "protocolVersions" --glob '!**/test/**'` - outside the tests only `scripts/acp-smoke.mts:60`, which offers `['0.8.0']`.
- `rg -n "SUPPORTED_PROTOCOL_VERSIONS|PROTOCOL_VERSION" packages/*/src` - read in `host.ts` and `nested.ts` only.
- `git log -S minimumReleaseAgeExclude` and `pnpm config list` - pnpm 11 holds a minimum release age, and each new `@cofold/*` version was let in by name; 1.0.0 was published on 2026-10-03.
- In the trial tree, `vitest run` after the offers were changed failed nine server tests on ahpd's own version (`plugin-install`, `server-configure`, `plugin-compat`); they pass on `a603dc9`, so they were the trial tree's and not the protocol's.

### Gaps

- The host answers the client's first supported entry, where the spec says the highest compatible one, and a malformed entry is skipped silently.
- `ahp.strict.schema.json` is regenerated by a bare vitest run only when it is missing, so after the bump it checks frames against 0.9.0 until somebody runs `pnpm schema`.

## Decisions locked in

| What | Source | Task |
| --- | --- | --- |
| Accepted versions are `SUPPORTED_PROTOCOL_VERSIONS` (`1.0.0`, `0.9.0`), the highest compatible offer wins, 0.8.0 and older are refused | Softov, 2026-10-03, asked "For now, which protocol versions does ahpd accept once it moves to the 1.0.0 package?": "1.0.0 and 0.9.0" | 02 |
| The choice is `negotiateProtocolVersion` itself, caret ranges included, so an offer of `1.1.0` is answered `1.1.0` | (defaulted: the package's function is the spec's rule, and a copy of it would drift) | 02 |
| An offer that is not a `MAJOR.MINOR.PATCH` string is refused with `-32602` naming it | (defaulted: `negotiateProtocolVersion` throws on one, and an uncaught throw is not a JSON-RPC error a client can read) | 02 |
| All five ranges become `^1.0.0`, the plugin's peer included | (defaulted: the peer moves with the sdk it is installed beside; the daemon installs plugins with `--legacy-peer-deps`) | 02 |
| `@microsoft/agent-host-protocol@1.0.0` goes in `minimumReleaseAgeExclude` | (defaulted: the pattern each `@cofold/*` release used) | 02 |
| A nested host may answer any version this host offered it | the request, 2026-10-03: "accept any version this host supports" | 02 |
| The test offers of `0.8.0` become `0.9.0`, or `PROTOCOL_VERSION` where the test is about the current version | the request, 2026-10-03 | 01 |
| The strict schema records the package version it was built from, and a bare vitest run rebuilds it when that differs from the installed one | the request, 2026-10-03: "rebuild when the installed protocol version differs" | 03 |

## Proposed architecture

- **Data flow** - `initialize` -> `negotiateProtocolVersion(offered)` -> the chosen version, `-32005` with `supportedVersions`, or `-32602` for a malformed entry.
- **Layer responsibilities** - root and packages: ranges and lockfile · sdk: `host.ts`, `nested.ts` and their tests · tools: the schema stamp · docs: `docs/AHP.md`, `README.md`.
- **Source-of-truth files** - [`code://packages/sdk/src/host.ts`](../../../../packages/sdk/src/host.ts), [`code://tools/schema.mjs`](../../../../tools/schema.mjs)
