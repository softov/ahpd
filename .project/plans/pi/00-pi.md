`packages/agent-pi` (`@ahpd/agent-pi`) is the pi backend: it implements the `Agent` interface of `packages/sdk` over pi's `AgentSession`, built in the daemon's process from `@earendil-works/pi-coding-agent` (decision [pi-is-embedded-not-spawned](../../decisions/pi-is-embedded-not-spawned.md)).
A pi session's events become chat actions, and pi's own session files are the catalogue.

## Packages

- [`code://packages/agent-pi`](../../../packages/agent-pi) - entry point `src/index.ts`; the plugin `src/plugin.ts`; the `Agent` `src/agent.ts`; a session and its turn lifecycle `src/session.ts`; the narrow seam over pi `src/backend.ts`; the event translation `src/mapping.ts`; models and thinking levels `src/models.ts`; the catalogue `src/catalog.ts`; transcripts `src/transcript.ts`.

## Contracts

- [`code://packages/sdk/src/types/agent.ts`](../../../packages/sdk/src/types/agent.ts) - `Agent` and `Start`, the only contract this package shares with the host.
- [`code://packages/sdk/src/types/session.ts`](../../../packages/sdk/src/types/session.ts) - `Session`, including the optional `forkPoint`, `endPoint`, `setTools`, `toolCallOwner`, `completeToolCall` and `clientGone`.
- [`code://packages/agent-pi/src/backend.ts#L28-L62`](../../../packages/agent-pi/src/backend.ts#L28-L62) - `PiBackend`, everything the session may ask of pi, and the seam a test replaces.

## Runtime path

```
piAgent() -> Agent.create(start) -> piSession -> first begin() opens pi (openPi -> createAgentSessionServices -> createAgentSessionFromServices)
  -> AgentSession events -> session.ts heard() -> mapping.ts mapEvent() -> chat/* actions
  -> agent_settled ends the turn -> watched turns kept in catalog.ts for Agent.transcript
```

## What stays

These are what this backend does well today, and no plan in this domain may lose them:

- reasoning streamed as its own part ([`code://packages/agent-pi/src/mapping.ts#L97-L116`](../../../packages/agent-pi/src/mapping.ts#L97-L116));
- pi's own `steer()`, plus the host-side queue with reorder and remove ([`code://packages/agent-pi/src/session.ts#L465-L555`](../../../packages/agent-pi/src/session.ts#L465-L555));
- model and thinking level chosen per turn ([`code://packages/agent-pi/src/backend.ts#L139-L159`](../../../packages/agent-pi/src/backend.ts#L139-L159));
- the turn closed on `agent_settled`, so a run pi retries is not reported finished early ([`code://packages/agent-pi/src/session.ts#L217-L231`](../../../packages/agent-pi/src/session.ts#L217-L231));
- sessions listed from pi's own files, so the `pi` CLI's sessions appear ([`code://packages/agent-pi/src/catalog.ts#L67-L102`](../../../packages/agent-pi/src/catalog.ts#L67-L102));
- the title kept in step with pi's session name both ways ([`code://packages/agent-pi/src/session.ts#L196-L204`](../../../packages/agent-pi/src/session.ts#L196-L204));
- project trust passed explicitly ([`code://packages/agent-pi/src/backend.ts#L84-L91`](../../../packages/agent-pi/src/backend.ts#L84-L91));
- pi opened lazily, once, on the first turn ([`code://packages/agent-pi/src/session.ts#L238-L274`](../../../packages/agent-pi/src/session.ts#L238-L274));
- `!command` run in a host terminal inside the turn list ([`code://packages/agent-pi/src/session.ts#L350-L403`](../../../packages/agent-pi/src/session.ts#L350-L403)).

## Known gaps

In the order they are worked:

1. Truncation is unreachable, a provider error shows as a finished empty answer, and the configured `model` is never used; plan [01](01-a-turn-ends-as-it-ended/plan.md).
2. Host and client tools never reach pi; plan [02](02-host-and-client-tools-reach-pi/plan.md).
3. pi never asks before a tool runs; plan [09](09-pi-asks-before-a-tool-runs/plan.md).
4. A transcript opens empty for any session this process did not watch; plan [10](10-pi-outlives-the-process/plan.md) replays it from pi's file.
5. `Start.instructions` is ignored; plan [03](03-the-host-instructions-reach-pi/plan.md).
6. No usage is reported; plan [04](04-a-turn-reports-its-usage/plan.md).
7. No fork; plan [05](05-a-chat-forks-from-a-turn/plan.md), after the contract change in [host 19](../host/19-a-fork-copies-through-the-turn/plan.md).
8. pi's edits never reach the host's changesets; plan [06](06-pi-edits-reach-the-changesets/plan.md).
9. Input from a client is not told apart from the terminal's; plan [07](07-remote-input-is-tagged/plan.md).

Dropped: a session store moving between hosts, plan [08](08-a-session-store-can-move/plan.md).

Not planned yet:

- Questions: pi's extension UI (`ctx.ui.confirm`, `select`, `input`) could become AHP input requests; today `answer` does nothing.
- Subagents: `Start.subagent` is never called.
