## Goal

A person who has just installed `@ahpd/server` runs `ahpd init`, answers a few questions at the terminal, and ends with a `config.json` and the plugins it names installed.
A first `ahpd` at a terminal with no configuration offers to run it; without a terminal it refuses as it does today.

## Reconnaissance

The files read are the `refs` above.

### Gaps

- A fresh install starts with no backend and refuses, naming `ahpd plugin install @ahpd/agent-claude`; host, port, token and folders are flags to know about beforehand.
- Neither cofold's terminal nor the server has a way to ask a question; Node's `readline/promises` is built in.

## Open questions

- A token: generated by init and written to a `connectionTokenFile` beside the configuration, typed by the person, or both offered?
- An existing `config.json`: refuse, edit what it has, or ask before replacing?
- A non-interactive form (`ahpd init --backend claude --host 127.0.0.1 ...`) for scripts: wanted now or later?
- An ACP backend needs a `command`: does init ask for it, or offer the known agents?
