The port is already there: `createHost` takes a list, `packages/sdk/src/types/agent.ts` imports no runtime value, and `@ahpd/agent-claude` is a package the host knows nothing about. What is missing is that the daemon hardcodes the list, so a second backend is a rebuild rather than an install. These five are in the order they should land, and each one is worth doing on its own. The first is built, the openai row became `@ahpd/agent-cofold`, and the rule the list now follows is [agent-package-only-when-it-brings-a-runtime](../decisions/agent-package-only-when-it-brings-a-runtime.md): a package is for a runtime, and a model is a configuration.

| | |
| --- | --- |
| load agents from configuration | `packages/server/src/main.ts` names `claude({ paths })` in the literal, so nothing else can be added without editing it. An `agents` key in `config.json` holds npm specs, resolved with `createRequire` against `~/.config/ahpd/package.json` so installing a backend is `npm i` in the config directory and `@ahpd/server` never grows a dependency on one. A package that throws on load is reported and skipped rather than taking the daemon down with it, and a duplicate `provider` refuses at startup: it is the routing key a client names in `createSession`, so a collision is a turn delivered to the wrong backend with nothing on screen to say so. Built as [plugin 01](../plans/plugin/01-plugins-load-from-configuration/plan.md), with `on` added by [plugin 02](../plans/plugin/02-plugins-subscribe-to-host-events/plan.md) |
| `@ahpd/agent-acp` | One bridge, several backends. `copilot --acp`, `codex-acp`, `gemini --experimental-acp` and `@deepseek-ai/dsh-acp` are the same seven methods and eight `session/update` variants, so the package is loaded once per backend with `provider` and the command as the only things that differ. `session/update` carries `agent_message_chunk`, `agent_thought_chunk`, `tool_call` and `tool_call_update`, which are `chat/delta`, `chat/reasoning` and the tool actions; `session/request_permission` is `confirm`. Capabilities come from the `initialize` reply and not from the typings - Copilot 1.0.80 answers `sessionCapabilities: { close, list }`, which `@zed-industries/agent-client-protocol@0.4.5` does not name - so which `Agent` members this build offers is decided at handshake. DeepSeek Harness is a full harness that already ships an ACP server, which is why it arrives here and not as a package of its own |
| ports through `Start` | An ACP agent asks the client for `fs/read_text_file`, `fs/write_text_file` and `terminal/create`, and `Start` carries `tools` but neither `resources` nor `terminals`. So a bridge builds its own file and shell access beside the ones the host already holds, and outside the `within()` check that is the only answer to whether a path may be reached. The backend below wants the same thing, which is what makes this worth changing rather than working around twice |
| `@ahpd/agent-cofold` | OpenRouter, Ollama, llama.cpp, LM Studio, DeepSeek and vLLM are one `/chat/completions` behind a `baseUrl` and a key. `@facio/agents` is already the harness - the loop, the tools, the policy, the store and the pause and resume - and `@facio/model-openai-compat` is the transport, so these are models inside one provider rather than four packages. `@ahpd/agent-cofold` is the AHP half: session config to `createAgent`, `RunEvent` to `chat/*`, approvals and questions to `inputNeededSet` and `confirm`, and `list()` and `transcript()` read from a facio `Store`. See [plugin 03](../plans/plugin/03-agent-cofold/plan.md) and the decision [agent-package-only-when-it-brings-a-runtime](../decisions/agent-package-only-when-it-brings-a-runtime.md) |
| native codex, if fork and rewind earn it | `codex app-server` is 82 client methods to ACP's seven, and four of them are optional members of `Agent` that the ACP path leaves empty: `thread/fork` for `Start.forkAt`, `thread/rollback` for `rewindAt` and `chat/truncated`, `turn/steer` for `Session.steer`, and `thread/list` with `thread/read` for the catalogue. It also takes host tools directly, through the `item/tool/call` server request, where ACP takes them only as an MCP server. The bindings are generated rather than written - `codex app-server generate-ts` - but the protocol is marked experimental, so the codex version wants pinning. Both paths are the same `Agent`, so choosing between them stays a config edit |
